# gnss-defense-edge

Tier-1 on-board console for the GPS Spoofing Sentinel project (Honeywell Kościuszkon 2026). A standalone Rust binary that loads two ONNX-exported XGBoost classifiers (TEXBAT L1 + AISSOU L2) and produces real-time spoofing verdicts via a native egui window.

The companion web dashboard lives in `../frontend/` (Tier 3, fleet/operator view); the FastAPI backend lives in `../backend/` (research / cloud side). See `Native_Edge_App_PRD_v2_for_ClaudeCode.md` for the full spec — this README assumes you've read §0 (production-vs-demo architecture).

## Build

```
cd gnss-defense-edge
cargo build --release
```

First build is ~2 min (pulls eframe + tokio + ort + ndarray dep graph and links a bundled libonnxruntime). Subsequent builds are seconds.

Output: `target/release/gnss-defense-edge` (~20 MB on macOS arm64). The 5 MB above the v2 §1 target buys us a self-contained binary — `ort` ships with `download-binaries` enabled, so there's no `libonnxruntime.dylib` install step on the demo laptop.

## Run

### Replay mode — deterministic, demo-realistic, fully offline

```
cargo run --release -- replay --scenario scenarios/texbat_spoof.csv
cargo run --release -- replay --scenario scenarios/aissou_channel_attack.csv --speed 0.5
cargo run --release -- replay --scenario scenarios/normal_waw_gdn.csv --looped
```

Speeds 0.25 / 0.5 / 1.0 / 2.0 / 4.0 supported. Replay reads the same 112-column CSVs the backend reads (`scenarios/` is a symlink to `../backend/app/scenarios/`) and runs ONNX inference locally — no network, no Python.

### Live mode — synchronized with the web dashboard

```
# In one terminal: backend (FastAPI on port 8000)
make backend          # from repo root

# In another: web dashboard
make frontend         # from repo root, opens http://127.0.0.1:3000

# In a third: native console, talking to backend over /ws/onboard
cargo run --release -- live --scenario texbat_spoof
```

The native app connects to `ws://127.0.0.1:8000/ws/onboard?scenario=texbat_spoof&speed=1.0` and uses each backend tick as a clock signal. **Features come from the local CSV** (`scenarios/texbat_spoof.csv`) and inference runs locally via ONNX. The footer renders a yellow `⚠ DEMO BRIDGE — production reads ARINC 429` banner so the architecture stays honest.

The backend's pre-computed `scores.{L1,L2}` / `verdict` / `top_reasons` fields in the WS payload are deliberately ignored. That's the entire point of Tier 1.

## ONNX export pipeline

Models live as `.joblib` bundles in `../models/`. Run once (or after a model refresh):

```
../backend/.venv/bin/python scripts/export_onnx.py all
```

This produces:
- `assets/texbat_l1.onnx` — `Pipeline(StandardScaler[t_int∈[30,100)], XGBClassifier)` baked into a single graph. Scaler is fit on `normal_waw_gdn.csv` baseline rows so Rust feeds raw features.
- `assets/aissou_l2.onnx` — bare `XGBClassifier` (no preprocessing per the joblib bundle).
- `assets/model_schema.json` — feature counts, thresholds, baseline-scenario reference.
- `tests/parity_fixture.csv` — 105 rows (normal + texbat + aissou scenarios) with python-computed `prob_l1`, `prob_l2`, `ratio_l1`, `ratio_l2`, `verdict` for the parity test.

Each model is exported in its own subprocess to avoid a known joblib double-load segfault inside `XGBClassifier.__setstate__` on xgboost 2.1.3.

### Threshold caveats

- TEXBAT threshold (0.05) is taken from the joblib bundle's `threshold` field. Baseline ratio ≈ 0.16, attack ratio peaks ~17×.
- AISSOU has **no calibrated threshold in the bundle** — we default to 0.5 for parity with `score_aissou(threshold=0.5)`. Empirically the L2 model saturates at p≈1.0 across all our synthesized scenarios (clean and attack), so its ratio is always ≥ 1.5 and the verdict pill leans CRITICAL on baseline scenarios. This is a real model/data issue, not a parity issue. Future work: re-train AISSOU on data closer to `generate_scenarios.py` distribution, or compute p99-on-clean as the threshold.

## Tests

```
cargo test --release
```

The single integration test, `inference_parity::rust_onnx_matches_python_onnx`, asserts max abs diff < 1e-4 on `prob_l1` and `prob_l2` for every fixture row. Verdicts are also cross-checked. Currently passes with max diff ≈ 6e-8 / 0.0.

## Limitations / future work

- AISSOU threshold not calibrated (see "Threshold caveats" above).
- No ARM cross-compile (PRD §1 explicitly out of scope).
- `top_reasons` are rule-based, not real SHAP — see `inference/reasons.rs`.
- No audio (PRD §1 out of scope; visual flash overlay is the only CRIT alert).
- Live mode requires the backend to start cleanly; on Python 3.10/3.13 + xgboost 2.1.3 the backend's `ml_service.warm_up()` segfaults during joblib double-load. Replay mode is fully independent of that path.
